# Plan: 21 observaciones Hosty (destino final: docs/plan-observaciones-2026-10.md)

## Context
Auditoría de 21 observaciones del usuario. Cada punto: causa raíz verificada en código + corrección. Al aprobar, este archivo se copia a `docs/`.

## Diagnóstico y corrección

| # | Causa raíz (verificada) | Corrección |
|---|---|---|
| 1 Versiones faltantes | Límite explícito `MAX_VERSIONS=15` en `daemon/src/provisioning/ServerInstaller.ts:45` y `ModLoaderCatalog.ts:9` (+ `.slice(0,15)` en fallback cliente `daemonApi.ts:278,285`). Además si upstream falla cae a lista estática sin 1.21.2. | Quitar slices, devolver todo (release; toggle "snapshots" opcional), cache en memoria con TTL, avisar en UI si es fallback. Filtro de texto/scroll ya existe. |
| 2 Terminal no copiable | `select-none` en la raíz `App.tsx:259` (heredado por la consola `OverviewTab.tsx:557-606`). | Quitar de la raíz, aplicarlo solo a chrome; `select-text` en consola; botones Copiar/Limpiar. |
| 3 Warning `sun.misc.Unsafe` | Externo: JOML de las libs de Minecraft en Java 23+. Hosty no añade flags. | No es bug de Hosty. Opcional: si Java ≥23 añadir `--sun-misc-unsafe-memory-access=allow` (gated por `EnvironmentDetector.majorVersion`; en Java antiguo rompe el arranque) + nota en docs. |
| 4 Menú contextual nativo | Ningún handler `contextmenu`. | Handler global en `main.tsx`: `preventDefault` salvo inputs/textarea/`data-allow-native-menu`; menú propio en consola (Copiar/Seleccionar todo/Limpiar). Mantener en dev. |
| 5 Parpadeo Reload packs | `onChanged` inline en `App.tsx:400` → `run` cambia → efecto `GamePacksDialog.tsx:42-46` re-fetch en cada render del socket; `useGames` reemplaza `games` siempre. | `useCallback`/ref estable, efecto solo `[open]`, mantener lista previa + spinner en botón, `min-h` fijo, no `setGames` si es igual. |
| 6 Código `SERVER_NOT_ONLINE` | `ErrorAlert.tsx:44-46` muestra siempre el badge con el código. | Quitar badge (o título localizado); añadir claves faltantes `INSTALL_CANCELLED`, `INTERNAL_ERROR`, `UNAUTHORIZED`, `INVALID_MESSAGE` en en/es; wizard/OriginStep/GamePacks usan mapeo i18n, no `err.message`. |
| 7 Buscador de mods | No existe; `ModJarManager` solo lista/borra. Core debe seguir agnóstico. | **Decisión: nada hardcodeado a Minecraft.** El manifest/driver declara `modSources` (proveedor, URL base de búsqueda/descarga, mapeo de campos y filtros loader/versión); el core solo implementa un cliente genérico de catálogo. Minecraft declara Modrinth (sin clave). CurseForge queda descartado por ahora (exige API key emitida a Hosty). Rutas genéricas `GET /api/instances/:id/mods/search`, `POST .../mods/install` (hash, destino según driver). Requiere #13. |
| 8 Autostart | `autostart` se guarda pero **nada lo consume** (no hay arranque al boot). | Implementar en boot del daemon y renombrar label a "Iniciar con Hosty" (en/es). |
| 9 Aikar flags | `AIKAR_FLAGS` hardcodeado en cliente (`EditServerModal.tsx:36-54`), pensado para Paper; `-XX:+UseG1GC` se duplica. | Driver declara `jvmFlagPresets` por loader (nuevo campo en `IGameDriverSummary`); UI muestra lista de presets con descripción, recomendado según loader (Aikar para paper/purpur; Fabric/vanilla: G1 básico/ZGC según Java), deduplicar flags. |
| 10 Recomendar Bridge | Wizard no lo ofrece. | Paso en wizard (tras customize) con beneficios y toggle por defecto activo si loader soportado; sigue disponible en Edit server. |
| 11 Install bridge | Cliente: `catch` vacío y flag local `bridgeInstalled`. Daemon: siempre `ok`, escribe stub si falta jar; en importados `loader` undefined → carpeta equivocada (Paper usa `plugins/`, no `mods/`). | Daemon verifica archivo escrito, falla si falta asset, devuelve ruta+estado real (`bridgeInstalled` desde disco en `InstanceInfo`); deshabilitar para loaders no soportados. Botón "Install Telemetry Bridge"; mensaje "reinicia" solo si el server está activo, si no "listo". Mostrar errores. |
| 12 Barra de título | Hover `surface-3` casi igual a `surface`. Marca duplicada (`TitleBar.tsx:52-57`). | Hover más fuerte + active/focus; quitar logo+nombre de TitleBar; agrandar logo/nombre del Sidebar (`Sidebar.tsx:139-142`). |
| 13 Import carpeta inválida | `FolderInspector` deja `gameId=null`; `importInstance` cae a `'minecraft'`; wizard descarta gameId/loader. | Daemon rechaza (`INVALID_FOLDER`) si no valida; wizard bloquea Continuar con mensaje; enviar `gameId`, loader, mcVersion y ajustes; ids únicos por colisión de nombre. |
| 14 Eliminar/menú servidores | No existe `DELETE /api/instances/:id` (solo `deleteInstance` interno). Sin favoritos. | Ruta DELETE (detiene/rechaza si corre; importado = solo desregistra, creado = borra archivos con confirmación). Menú contextual en sidebar (añadir `@radix-ui/react-context-menu` + botón ⋯): Abrir, Editar, Renombrar, Favorito, Abrir carpeta, Quitar/Eliminar (texto aclara que no borra carpeta si es importado). `favorite` en `InstanceSettings`. |
| 15 Flujo inicio | Wizard siempre abre en `origin` (`CreateServerWizard.tsx:97-138`). | Flujo: Comenzar → Juego (solo drivers disponibles) → Crear/Importar → pasos. Import valida contra el juego elegido (`validateInstallation` del driver). Quitar `OriginStep`/duplicado de botones. |
| 16 Addons desacoplados | `GET /api/game-packs` solo lista packs externos; Minecraft (código) y PZ/Hytale (builtin) no aparecen; hay `'minecraft'` hardcodeado en `GameDriverRegistry:17`, `InstanceManager`, `FolderInspector`, `wizardPlan`. | Fase 1: exponer builtins en `getPackInfos()` (`source:'builtin'`, solo lectura). Fase 2: mover PZ/Hytale a packs en carpeta (seed desde `bundle.resources` en `lib.rs`), logos vía `/api/games/:id/logo`. Fase 3: API instalar/desinstalar/untrust pack (zip + `validateManifest`, safe-path), "abrir carpeta", soporte campos `custom`. Minecraft permanece con driver de código (trust pre-sembrado) hasta eliminar hardcodes. Divergencia: docs dicen `%APPDATA%\Hosty`, app usa `com.hosty.app`; corregir docs. |
| 17 PZ build 42 | Manifest solo `stable`/`unstable`; `pzBranch` hardcodeado cliente/daemon; `-servername servertest` fijo. | Diferido (pedido). Anotar: ramas Steam como opciones del manifest, campo genérico de rama, `serverName`. |
| 18 Idiomas | `SUPPORTED_LANGUAGES=['en','es']`, toggle binario `Sidebar.tsx:203-210`. | Selector dropdown; daemon `GET /api/locales` + `/:code` desde carpeta `locales/` (junto a `games/`), `addResourceBundle` (mecanismo ya usado en `useGames`), `fallbackLng:'en'`. Paquetes iniciales: en, es-ES, es-419 (Latinoamérica), zh-CN, hi, pt-BR, pt-PT (los 4 idiomas más hablados + variantes); test de paridad solo para en/es. |
| 19 Logo bienvenida | Tile con `border bg-surface p-3 rounded` en `WelcomeEmptyState.tsx:186` y `DaemonGate.tsx:17`; `logo.svg` es un avatar DiceBear Critters (revisar licencia/atribución). | Quitar borde/tile, logo circular/squircle recortado; definir marca propia: crear SVG propio de Hosty (estilo/animación a elegir; DiceBear es de uso libre, se conserva hasta entonces). |
| 20 Instalador e icono | `tauri.conf.json` NSIS solo `installMode`; sin imágenes/hooks; `icon.png/ico` cuadrados a sangre; sin icono de ventana explícito. | NSIS: `installerIcon`, `headerImage`, `sidebarImage`, `languages`+`displayLanguageSelector`, `installerHooks` (.nsh) para sembrar packs/idioma; selección de packs mejor como paso in-app post-instalación (template NSIS custom = alto mantenimiento).
